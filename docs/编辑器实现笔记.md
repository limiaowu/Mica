# 编辑器实现笔记（深水区）

> 从 CLAUDE.md 拆出，集中放「公式/代码块、行内嵌入、HTML 表格、整体缩放」这些已完成功能的实现细节与踩坑。
> 改这些功能前先来这里找对应小节；常驻的架构总览/约定仍在 [CLAUDE.md](../CLAUDE.md)。表格的设计/任务清单另见 [表格HTML改造计划.md](表格HTML改造计划.md)。

- **公式 = KaTeX，代码块 = CodeMirror 6**（2026-06 接入，见 `createEditor.ts`）：
  - 公式 `@milkdown/plugin-math`：行内 `$...$`；**块级公式必须用多行 `$$` 围栏**（`$$` 单独成行、内容在中间），单行 `$$...$$` 会被 remark-math 当作行内显示公式塞进段落。katex CSS 在 `main.ts` import。该包 npm 标 deprecated 且**停更在 7.5.9**（math 没进 `@milkdown/kit`、kit 无 math 导出；只有 crepe 内部自带），但它仍是唯一的 à la carte 官方公式包，可用。
  - **行内公式 + 行内代码 = 原子节点 + 共用 nodeView（inlineEmbedView 三态）**（2026-06，历史绕了一圈见下「历史决策」）：二者都是 `atom` inline 节点（区分符 `$`/反引号由 nodeView 渲染、非真实字符）。**为什么用原子而非标记**：原子节点的**光标语义干净**——节点前/后是清晰文本位置、方向键整体跳过、`a`code`b` 中能点到 `a|` 和 `|b` 的缝；而 commonmark 的 `inlineCode` **标记**（`code:true`）有 ProseMirror 老毛病：光标卡在 mark 边界、进不去缝、整行只有代码时退不出来（实测一堆 bug，已弃）。代价：反引号整体增删、不能单删一个（用户认可）。**块级公式**在 `mathView.ts`（`createMathBlockView`）。
    - 行内代码节点 `inline_code`（`$nodeSchema`，parse/serialize 对接 mdast `inlineCode`）。**坑**：得把 commonmark 的 inlineCode 标记插件按引用过滤掉（`commonmarkNoInlineCode`），否则标记与节点都认领 mdast `inlineCode` 冲突；`$markSchema/$useKeymap` 返回 `[ctx,x]` 元组而 commonmark 是 `.flat()` 过的，过滤集要把数组型导出**展开**后再排除（见 `inlineCodeMarkPlugins`）。
  - **公式/代码存储 & 空节点必删**：行内值存**节点文本内容**（`content:'text*'`），块级公式存 `attrs.value`（别搞反）。**空内容提交(blur/deselect)时直接删整个节点**——空行内公式被序列化成 `$$`（再读盘/切源码变行间公式，实测根因！）、空行内代码成对反引号，都破坏 .md 往返，故不留（占位即弃）。
  - **三态交互**（inlineEmbedView，对标 Typora）：相邻判断由 `inlineEmbedRevealPlugin` 经 node decoration 的 `spec.embedActive` 传进 `update(node, decos)`。① **渲染态**(光标远)→KaTeX/`<code>`；② **显露态**(光标相邻)→「源码 + 区分符(+公式预览)」但**不抢焦点**；③ **编辑态** `<input>` 失焦/方向键到边界(`exitTo`)提交。入口：渲染态点击(NodeSelection)→`selectNode`、方向键(`enterEmbedOnArrow`)、退格跳进(`enterEmbedOnBackspace`)、插入(`insertAtomNode`)。块公式用 `<textarea>`。`.milkdown .katex` 用 1.12em。
  - **gapcursor 修「块在文档首/尾、上下无处落光标」**：`.use($prose(() => gapCursor()))`，包来自 `@milkdown/prose/gapcursor`（随 `@milkdown/prose` 已装，**无需新依赖**）；其自带样式描边是黑色，已在 `editor.css` 用 `--mica-fg` 重写 `.ProseMirror-gapcursor` 跟随明暗。注意：**源码模式在块前敲空行会被 markdown 规范化吞掉**（前导空行无意义，属正常），改用 WYSIWYG 在块前另起一行。
  - **代码块在文档首行、↑/← 退出时自动在其前面新建一行**：代码块的 CM 实例由 `@milkdown/components` 管，其 `maybeEscape` 在块位于 doc 首位时执行 `TextSelection.near(resolve(0),-1)`，落到 doc 顶层（非 inline 容器）→ **既报 `TextSelection endpoint not pointing into a node with inline content (doc)` 警告、又移不动**。修复在 `codeSetup.ts` 的 `leadingEscapeKeymap`（`Prec.highest` 抢在组件键位前）：判断「文档首块是代码块」且「第一个 `.milkdown-code-block` DOM 含当前 `cm.dom`」时，在 doc 最前插空段落并把光标放进去。**注意别用 `posAtDOM(cm.dom,0)` 判断「块前」——它对 nodeView 内部 DOM 返回的是块内位置（depth=1），不是块前**（踩过坑）。PM view 由 `createEditor` create 后缓存成模块变量 `proseView`，经 `() => proseView` 闭包传进 `buildCodeMirrorExtensions`（公式块的同款逻辑在自家 nodeView 里，见上）。
  - **输入「闭合区分符」才触发，绝不拦开头字符**（2026-06 关键修复）：`` `x` `` 闭合反引号 → 行内代码节点（**自写 `inlineCodeInputRuleAtom`**：`InputRule(/(?:`)([^`]+)(?:`)$/`)，对标官方 `mathInlineInputRule` 的写法、`replaceWith` 成原子节点）；`$x$` 闭合 → plugin-math 官方 `mathInlineInputRule`；`` ``` ``+空格 → `createCodeBlockInputRule`（代码块）；`$$ ` 行首 → `mathBlockInputRule`（公式块）。**绝不再用 `handleTextInput` 拦开头的 `$`/反引号**——那是历史上一切乱象的根因：拦开头字符直接插空原子节点，导致①单个反引号/`$` 即触发、空节点，②三反引号被吞、打不出代码围栏，③`$5` 误判公式。改成「闭合触发」后全消，且与 Markdown 直觉一致。公式/代码 nodeView 的 `openEditor` 用 rAF + `setTimeout(60)` 双重兜底聚焦。
    - **补「先摆好空区分符对、光标置中再输入」的转换（`fillEmptyEmbedPair`，handleTextInput 直接 prop）**：用户先打 `` `` `` 或 `$$`、把光标放中间再往里填时，闭合输入规则不会触发（闭合符已在光标之后）。故加一条**极窄**的 handleTextInput：仅当「输入单个非空白、非区分符字符」且「光标前一字符 == 后一字符 == 同一区分符」时，把这对空区分符替换成含该字符的原子节点并选中打开编辑框。**这不违反「绝不拦开头区分符」**——它要求用户已显式摆好一对空区分符且光标在其间；输入区分符本身时 `return false`，故三反引号围栏 / `$$ ` 公式块 / 字面 `$5`（只一个 `$`）都不受影响。
  - **`$$ `/`$$`+Enter 建出的空公式块自动进编辑框（`mathBlockAutoEditPlugin`，appendTransaction）**：官方 `mathBlockInputRule`（`/^\$\$\s$/`）只 `setBlockType` 不选中新块 → nodeView 停「点击编辑公式」渲染态。故加 appendTransaction：当事务 `docChanged` 且光标落在「空 `math_block` 内部」或「紧贴其前」时，补一个 NodeSelection 选中它 → 触发 nodeView `selectNode` 打开编辑框。**不替换官方 input rule**（避免打错位置风险），只事后补选区；纯导航无 docChanged、被排除，不误触。
  - **点击正文最末块「下方」空白 → 自动到文末（末块非空段落则补一空段落）**：对标 Typora，`createEditor` 给 `wysiwygEl` 挂 `mousedown`（`onClickBelowContent`），判断 `e.clientY > 最后一块底部` 才处理，否则交回 ProseMirror。
  - **段落首行缩进**：设置项 `EditorFirstLineIndent` → `editor.config` 推 `firstLineIndent` → web 给 `body` 挂 `.first-line-indent` 类，`editor.css` 用 `.ProseMirror > p { text-indent:2em }`（**只缩顶层段落，不动列表/引用/表格**，避免缩进叠加）。纯 CSS、不重建编辑器。**列表协调**：首行缩进模式下顶层 `ul/ol` 加 `margin-left:1em` 整体右移（默认列表项目符号在 padding 区、比 2em 首行缩进还靠左，看着突出；只移顶层、嵌套保持相对缩进）。改缩进量见 `editor.css` 该 `margin-left`。**两处入口同一设置**：设置页（编辑器分类）+ 格式菜单 `FirstLineIndentMenu`（`OnToggleFirstLineIndent`）；`PushEditorConfig` 里同步菜单勾选。
  - **行内嵌入空节点**：无选区经快捷键/菜单插入空行内代码/公式时，编辑 `<input>` 的 `min-width` 必须为 `0`（配 `field-sizing:content`），否则空内容也撑出一段空白、两区分符不贴合。见 `editor.css` 的 `.mica-embed-src`。
  - **设置页分类**：「外观」只放主题；字体/字号/行宽/行号/首行缩进/缩放等编辑器内容项归「编辑器」分类（2026-06 调整）。
  - **`.milkdown .editor`（ProseMirror 可编辑元素）必须 `white-space: pre-wrap`**：否则控制台报「ProseMirror expects the CSS white-space property…」且多空格/行尾空格渲染异常（等价官方 prosemirror.css）。
  - **任务列表**：gfm 只扩展了 `list_item` 的 `checked` 属性 + `- [ ] ` 输入规则，**没有现成命令**。自写 `toggleTaskListCommand`（已在列表内→切 `checked: false↔null`；不在→`wrapInList(bullet_list)` 后把 list_item 标 `checked:false`）。任务项只渲染 `<li data-item-type="task" data-checked>`（crepe 才带勾选框 UI），故**勾选框是 `editor.css` 纯 CSS 画的**（`::before`/`::after`，放在 li 内左侧 padding 区以便点击命中）；**点击切换靠 `createEditor` 的 `handleClickOn` 按点击 x 坐标判断**（只响应左侧约 1.5em 的勾选框区，点正文不切换）。
  - **系统主题色 `--mica-accent`**：`SyncEditorTheme`（EditorTheme.cs）经 `theme.update` 的 `vars` 把 Windows 强调色（深色取 AccentLight1）推给编辑器，用于任务勾选框、表格列宽手柄等；CSS 用 `var(--mica-accent, var(--mica-link))` 兜底。这是除明暗 mode 外、宿主向编辑器推 CSS 变量的范例（其余颜色仍在 editor.css）。**坑：`--mica-accent` 不能在 `body.dark` 里再定义**——宿主把它写到 `:root`(html)，而 `body.dark` 写在 `body` 上、对 body 内元素更近，会盖掉宿主推送的真实强调色 → 深色下行内代码等用了固定色而非系统色。`:root` 的默认值已够作「无宿主」时的兜底，深色不要再设。
  - **表格行别太高**：单元格内段落默认带上下 margin 会把行撑高，`editor.css` 用 `.milkdown th>*,.milkdown td>* { margin:0 }` 压平。表格圆角靠 `border-collapse:separate + overflow:hidden`（collapse 下 border-radius 不生效）。
  - **表格 = HTML 表格节点（2026-06 全面改造，替换原 GFM 管道表格）**，核心在 `web/src/editor/htmlTable.ts`，**完整设计/任务清单见 [表格HTML改造计划.md](表格HTML改造计划.md)**：
    - **为什么换**：GFM 管道表格无法表达合并单元格/多级表头/每表样式。改用 `prosemirror-tables` 的 `tableNodes` 自建 `table/table_row/table_cell/table_header` 节点（自带 rowspan/colspan + `mergeCells`/`splitCell`/`CellSelection`，无新依赖），**不强制表头行**（th/td 任意混排 → 多级表头天然支持）。
    - **存储 = .md 里嵌真实 `<table>` HTML**：序列化时 `table` 节点的 `toMarkdown` 自己拼成**单行无空行**的 `<table>…</table>`（无空行否则 remark 拆成多个 html 节点而解析失败），用 `state.addNode('html',…)` 发出；单元格内部内容用 `DOMSerializer` 序列化（正确处理 strong/em/link）、单段落解包。反序列化：`$remark` 变换把 `<table` 开头的 html 节点（及粘贴的 gfm `table` mdast）统一改类型成 `mica_html_table`（避开「commonmark html 节点匹配任意 type==='html'」冲突），`table` 节点 `parseMarkdown` 用 `DOMParser.fromSchema` 还原成 PM 节点再 `state.push`。
    - **坑（往返必踩）**：remark 往返后独立的 `<table>` 常被当成**行内 html 包进一个段落**（表格塞进段落→报 `Cannot create node for paragraph`、表格被丢弃 → 「切源码再切回表格没了」）。故 `$remark` 变换里 `liftTablesFromParagraph` 把段落中的表格 html **提升到块级**，前后非空文本仍留作段落。改往返相关逻辑务必保留这步。
    - **结构 vs 装饰**：合并(colspan/rowspan)、列对齐(text-align)、整表对齐(margin) → **标准内联 HTML/style**（可移植）；圆角/线宽/三线表预设 → **table 的 `data-radius`/`data-border`/`class="mica-table-3line"`**（.md 干净、每表单独设，别的渲染器忽略时仍是普通表格）。**关键**：`toDOM`（编辑器实时渲染）把这些写成**内联 style** 即时生效；`serializeTable`（写 .md）写成 **data-\*/class**——两者都从同一份 `node.attrs` 派生。
    - **从 gfm 按引用剔除一整组表格插件**（schema/plugin/输入规则/键位/15 个命令），保留 `remarkGFM`（删除线/任务列表/autolink 仍需）、删除线、任务列表扩展；手法同 `commonmarkNoInlineCode`（元组型导出展开后排除），见 createEditor 的 `gfmNoTable`。注册 `tableEditing()`（cell-selection/良构维护）+ 自绑 Tab/Shift-Tab 单元格导航（`goToNextCell`）。**未启用 columnResizing**（故无 `.tableWrapper`；列宽拖拽待后续）。**宽表横向滚动**：`tableSchema.toDOM` 把表外包一层 `['div',{class:'mica-table-scroll'},['table',…]]`，CSS `.mica-table-scroll{overflow-x:auto}` → 宽表只在本层内横向滚动、不撑出整个文档的横向滚动条（对标 Typora）。**只有实时渲染加这层**——`serializeTable`(写 .md)/`parseHtmlTable`(读) 都不涉及它，.md 里仍是裸 `<table>`。**坑**：`nodeDOM(pos)` 现在返回外层 div（= 滚动视口）。浮动条 `positionBar` **必须用这个外层 div 的 rect 定位、不能用里面的 `<table>`**——否则对齐的是表格真实边缘/中线，拖横向滚动条时浮动条会跟着滚（踩过坑）。自适应窄表也对得齐：外层满编辑宽、表靠 margin 在其中左/中/右就位，与浮动条按同一 align 在外层内就位**重合**。`mousemove`/`posAtDOM` 仍用 `closest('table')` 不变。
    - **列对齐**：无 keepTableAlignPlugin，故 `setColumnAlign` 用 `TableMap` 逐个写该列所有单元格（合并单元格去重）。**整表对齐**写 `table.attrs.align` → toDOM 渲 margin（故表格 `width:auto;max-width:100%`，width:100% 时 margin:auto 无效）。
    - **插入 = WinUI 交互式启动器**（`MainWindow.Table.cs` 的 `ShowInsertTableDialogAsync`，菜单/Ctrl+Shift+T 开）：单向预览——行/列数 + +行/+列(边缘追加保留合并) + 点选相邻格「合并/拆分」；选项有首行表头、内容对齐、整表宽度(占满/自适应)、整表对齐、样式预设、圆角、线宽。**确定后宿主直接拼 `<table>` HTML（`BuildTableHtml`，含 class/data-\*/colspan/rowspan）发 `editor.insertTable {html}`** → web `insertTable(html)` 用 `parseHtmlTable` 还原插入。**启动器只做整表统一内容对齐，逐列对齐插入后右键改；改尺寸 NumberBox 会清空已设合并（+行/+列 保留）**。宽度默认**占满**(width:100%)，自适应时 `width:auto` + margin 对齐才生效。
      - **数字输入用 NumberBox + `SpinButtonPlacementMode=Compact`**（与设置页字号同款，旋钮悬停/编辑才弹、平时只显数字；**别用 Inline**——窄框里旋钮+数字挤一起看不清）。行≤50/列≤20/圆角0–24/线宽0–6，到边界在状态条提示；`+行/+列` 同限（web 端右键加行列**无限**，对标 Typora）。**圆角框在 三线表/无框线 预设下禁用**（强制直角）。
      - **固定尺寸 + 单滚动条**：`dialog.Content` = **定宽高 `Grid(540×560)`**——顶部选项(Auto) + 预览(Star，**只它内部滚动**) + 按钮(Auto)。固定大小修「连点 +行 弹窗变高、控件下移 → 鼠标下的按钮从 +行 变 -行」；预览独占滚动修「主面板 + 预览两个滚动条」。
      - **页脚按钮自定义**（不用 ContentDialog 自带 PrimaryButton/CloseButton——它们拉满页脚整列过长，且 Style 改宽度被模板 local 值压过无效）：按钮行放在 `contentRoot` 底部 Auto 行，定宽 ~96、accent 套 `AccentButtonStyle`，点「插入」置 `confirmed=true` 再 `dialog.Hide()`。
      - **记住上次选项 + 重置**：对话框各项存进程内 `static _tbl*` 字段，重开沿用；标题改成自定义 `Grid[「插入表格」+ 右侧「重置」按钮]`（`dialog.Title` 接受元素），重置恢复出厂默认。`整表宽度` 选项文案用「最大宽度/自适应」（短、combo 不过宽）；数字框 `Width=96` 左对齐留白。
      - **预览真实反映样式**：`tableFrame` 按预设画整表边框/圆角/宽度对齐，单元格按预设画内框线 + 表头/斑马/彩虹底色；**每个单元格都铺透明刷**保证整格可点击命中（`Background=null` 的 Border 空白区不命中 → 「只点中间小条才选中」的根因）。**全框线/普通的单元格只画「内部」右+下线，最右列不画右、最末行不画下**，外缘交给 `tableFrame` 四周边框收——否则边缘线与外框叠成双倍宽（「右侧/底部线更粗」的根因）。**背景卡片 `previewBorder` 始终占满预览区（Stretch）**，表格在其中**垂直居中**：靠 `innerHost`（`MinHeight` 由 `previewScroller.SizeChanged` 钉成视口高度）——表格少时居中、表格多时随之变高并内部滚动（仅一个滚动条）。
      - **`ContentDialog` 默认最大宽度偏小会裁掉 540 宽内容右侧**（取消按钮/表格右边被切、且无横向滚动）：`dialog.Resources["ContentDialogMaxWidth"]=720`。标题栏 `titleBar` 定宽 540（与内容一致）才能让「重置」靠到最右。
    - **不能嵌套表格（对标 Typora：无任何提示）**：光标在表格里时插入表格 → **什么都不弹、不做**。两条入口都先问 web 的 `isInTable`：①**快捷键** Ctrl+Shift+T 在 `createEditor` 的 `Mod-Shift-t` keymap 内自查，不在表格才转 `host.shortcut insertTable`；②**菜单**「插入表格」`OnInsertTable` 发 `editor.checkInsertTable` → web `tableSetup.checkInsertTable()` 查后同样处理（在表格内直接 return）。
