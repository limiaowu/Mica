## 地基：图片引用解析器（最关键，先做）

一切功能都依赖一个**健壮的 .md 图片引用解析器**。输入：note 的 .md 文本 + 笔记绝对路径 + 笔记本根；输出：每个本地图片引用 `ImageRef`：
- `rawSrc`：.md 里**原样**的 src 字符串（改写时按它精确替换，避免编码/括号问题）。
- `resolvedAbs`：解析成的绝对文件路径（`noteDir` + 相对，规范化 `..`）。
- `category`：`Mica`（`<根>/.mica/assets/<noterel>/`）/ `SameDir`（与 .md 同级）/ `AssetsSub`（`assets/` 子夹）/ `Embedded`（data: base64，无文件）/ `External`（http/绝对/笔记本外，**不碰**）。
- `exists`：目标文件在不在（找断链）。

**承重坑**（解析器必须处理）：① 两种语法 `![alt](path)` 与 `<img src="path">`；② markdown 路径可能 `<带空格的路径>` 或 `%20` 编码；③ 改写时**用 rawSrc 精确替换**、并保持原编码风格（同名去重产生空格时要么用无空格后缀 `-1`，要么按原风格编码）；④ `.mica` 的 src 形如 `../.mica/assets/<rel>/img.png`，`../` 层数随深度变化。
建议**宿主侧**实现（维护操作都是文件系统活）：新 `ImageRefParser`（纯函数、好测）。

## 功能与架构

新服务 `NotebookMaintenanceService`（或扩 `FileService`），都建立在解析器上：

- `ScanNotebook(root) → NotebookImageReport`（只读，地基）：遍历所有 .md → 每篇的 `ImageRef[]`；汇总：各 category 计数/总大小、断链引用、`.mica/assets` 下的**孤儿文件**（无任何笔记引用）、`.mica/assets/<noterel>/` 对应笔记已不存在的**孤儿目录**、用 base64 内嵌的数量。
- **孤儿清理**：**只对 `.mica/assets/` 安全**（该目录是 Mica 独占管理的）。同级/assets 模式的图与用户其它文件混在一起、无法安全区分，不做自动清理（或仅在「导出规范化」时处理）。删一律走回收站 + 二次确认 + 先 dry-run 预览。
- **图片存储迁移**（改设置后）：逐笔记把「不在目标模式位置」的被引用图移到目标位置 + 改写该篇 src；同名去重。复用类似 `CarryAssetsAsync` 的「搬 + 改写」逻辑。**这一步天然顺手实现任务1**（搬被引用的散图）。
- **导出规范化**：把笔记本 .md 拷到新文件夹，所有图统一成选定布局（如 `<noterel>.assets/`）；base64 内嵌可选「抽出成文件」；产出干净可移植副本。
- 所有批量操作：模态进度（参照 `MigrateFolderAsync` 的进度模式）；若有笔记正打开，改写后 `editor.load` 重载（让 web 按新 src 重解析，参照笔记本迁移收尾）。

## 可视化界面（任务4）

独立「笔记本维护」覆盖页（像设置页那样整层覆盖 `EditorSurface`）：
- 每个笔记本：图片数 / 总大小 / 按存储模式分布（饼图或条形）/ 孤儿数 / 内嵌数 / 断链数。
- 不一致报告：混用多种模式的笔记、断链、孤儿，可展开看具体哪些笔记/文件。
- 动作区：「清理孤儿」「统一存储到 ___」「导出规范化副本」，带 dry-run 预览 + 进度 + **前后对比统计**（满足「看到实际效果」）。
- 视觉：图表、文件大小条、进度动画、结果摘要——这块刻意做丰富。

## 入口位置（已定）

**详情页主入口 + 笔记本主页多选批量，不单独占侧边栏。** 理由：
- 扫描模型天生是「一个笔记本=一个根」→ 详情页本就在看单个笔记本（已有路径/统计/封面），scope 完全吻合、上下文连贯，作主入口。
- 主页卡片已有多选 → 选中多个卡片后工具条「批量分析/清理」，对每个根跑同一套，适合跨笔记本概览。
- 侧边栏独立导航项被否：维护是低频运维操作、不值常驻一级导航，且独立入口还得再做一个笔记本选择器，与主页多选重复、更重。
- 仪表盘本身＝覆盖页（像设置页整层盖 `EditorSurface`），从两个入口进、预载对应笔记本。
