# 主题系统计划

> 对标 [图片功能计划.md](图片功能计划.md)。记录主题系统的设计决策、分期任务、关键约定，防止对话 compact 后丢上下文。
> 本文件只管「设计与进度」，实现细节/踩坑随做随补到 [编辑器实现笔记.md](编辑器实现笔记.md) 或 [开发笔记.md](开发笔记.md)。
> **排期上在「文件树重写」之后做**（见下「排期」）。token 地基可随时便宜插入。

## 背景：现状底子（2026-06 盘点）

主题的「调色」层其实已走了一大半：

- **编辑器（WebView）颜色已 token 化**：[web/src/styles/editor.css](../web/src/styles/editor.css) 顶部 `:root` 一套亮色变量（`--mica-fg`/`--mica-accent`/`--mica-surface`/`--mica-table-*`/`--cm-*` 语法高亮等），`body.dark` 一套覆盖。本质就是「一套主题 = 一组 CSS 变量值」。
- **host→web 主题管道已存在**：[MainWindow.EditorTheme.cs](../Mica/Views/MainWindow.EditorTheme.cs) 的 `SyncEditorTheme` 经 `theme.update {vars, mode}` IPC 推变量，[web/src/main.ts](../web/src/main.ts) 的 `on('theme.update')` 写到 `:root` + 切 `body.dark`。目前只推了 `--mica-accent`（系统强调色），其余颜色住 CSS。
- **原生明暗已瞬切**：`ApplyThemePreference` 用 `RequestedTheme`（Light/Dark/Default），所有 Fluent `ThemeResource` 自动重算。
- **选中的主题偏好已存** `settings.json` 的 `Theme` 字段（`SettingsService.ThemePref`，目前值是 `System`/`Light`/`Dark`）。

结论：**剩下的不是「调色」，而是「装饰层」与「原生壳换肤」**。

## 热重载能力（已确认）

- **WebView2：能且轻**。主题=一组 CSS 变量值（+ 可选 `data-theme` 属性），切换=推 `theme.update`，不刷新、瞬间生效。装饰层同理（DOM 重建）。→ **能放进 WebView 的 themed 表面尽量放进去**。
- **原生壳：明暗 + 强调色瞬切；自定义画刷需「抖一下」**。运行时改 ResourceDictionary，WinUI 不自动重算已渲染的 `{ThemeResource}`：稳妥做法是自定义画刷走 `ThemeResource`、换主题时整体替换 merged dictionary 再把 `RequestedTheme` off→on 强制重解析。
- **真正切不动的是「重装饰原生壳」**（如给原生标题栏贴像素木纹）：可能需重建可视元素，做不到无缝。→ 原生壳只保证「颜色/强调色/背景可切换」，重装饰放 WebView。

## 核心架构：主题分三层（关键决策）

**不学 Typora「一主题=一坨自由 CSS/JS」**——那是为用户自写主题设计的，安全/维护负担大，而 Mica 主题是**一方内置、自己掌控**，不需要那种自由度。拆三层，难度递增：

| 层 | 内容 | 难度 | 覆盖谁 |
|---|---|---|---|
| **① Token 层** | 颜色/字体/圆角/间距一组变量 | 低（已有） | 明暗、Claude 暖色、四季底色 |
| **② 装饰层** | 贴图/SVG/像素边框，按锚点摆放 | 中（建一次引擎） | 花草、西瓜、星露谷木框 |
| **③ 行为层** | 动起来的（桌宠、季节飘落动画） | 中高（各自单写） | clawd 桌宠、动画 |

### 主题数据形态

主题 = **清单(JSON) + token 集 + 可选资源文件夹 + 可选装饰/桌宠规格**，不是裸 CSS。形如：

```jsonc
{
  "id": "spring", "name": "春", "mode": "light",
  "tokens": { "--mica-surface": "#fffdf8", "--mica-accent": "#6aa84f", "...": "..." },
  "decorations": [
    { "asset": "flower-corner.svg", "anchor": "bottom-left", "layer": "editor-bg", "opacity": 0.35 }
  ],
  "mascot": null
}
```

- **token** 同时驱动 WebView 编辑器（推 `theme.update`，已通）与原生侧（映射一个子集到 XAML 画刷）。
- **decorations** = 声明式数组：编辑器内加一个**不可交互的装饰图层**，按锚点（四角/页边/标题栏）把贴图摆上去。→ 四季 ≈ 4 套 token + 4 包贴图 + 摆放列表；星露谷 ≈ token（像素字+木色）+ 像素边框资源 + 摆放。**每套主题主要是「数据+素材」，几乎不写 bespoke 代码**——这是把「复杂主题」驯服成可批量产出的关键。
- **mascot（clawd 桌宠）** = 单独做成**通用「桌宠 widget」**（精灵图 + 待机动画 + 可定位），任何主题用 `mascot` 配置启用，**别写死成 Claude 专属**。做一次，复用。

### 渲染位置约定

- 编辑区装饰一律走 **WebView**（热重载 + CSS/SVG/canvas 简单）。
- 仅标题栏/侧栏的原生装饰才用 XAML Image/Border 层。
- 绝大多数装饰点子在书写区周围 → WebView → 简单。

## 存储约定（已确认）

按「读写频率 / 谁拥有」拆开，直击「settings.json 越加越大 + 主题通常只读不写」的顾虑：

- **「选了哪套主题」+ 用户颜色 override 补丁** → 留 **settings.json**（就是 `Theme` 字段 + 一个小 override，极小，跟其它偏好一起读写）。
- **主题「定义本身」（token/装饰规格/素材）** → **绝不进 settings.json**。内置主题作为**应用资源随包发**（跟编辑器产物一样待遇），只读、进版本库。
- **以后若允许用户自定义主题** → 存 `LocalAppData/Mica/themes/` 下**一主题一文件**，别堆进 settings.json（契合「文件系统即管理」）。

净结果：settings.json 只存**指针**（选中 id + 小 override），主题**内容**是只读文件。

## 可视化主题设计系统：暂不做（已确认）

- 可视化编辑器只有「用户自己造主题」才值，但招牌主题是**素材+行为驱动**的，调色滑块产不出「西瓜+桌宠」，只能调颜色——主题里最不特别的部分。
- 它本身是大功能（界面+实时预览+持久化+校验+导入导出），边际价值低。
- **折中**：以后真要开放，做一个薄薄的「改当前主题的几个颜色」（基础主题 + 颜色 override 补丁），是完整编辑器的 10% 工作量、覆盖 90% 欲望。完整设计系统**无限期推迟**。
- **唯一现在值得做的「设计系统」**：把 token 列表**集中 + 写文档**，给**作者（你自己）**快速产主题用，不是给用户的 UI。

## 计划内置主题

- **WinUI3 / Fluent Design 2**（= 目前这套，作为默认）
- **春夏秋冬**：四季各一套底色 + 装饰元素（春-花草、夏-橘子西瓜…）。素材较重。
- **星露谷物语**：像素字 + 木色 token + 像素边框/滚动条素材。素材较重。
- **Claude**：Claude 网页版暖色配色 + clawd 桌宠。**低素材成本**（主要是配色+桌宠），适合做第一个非平凡主题的纵向薄片。

## 排期（建议顺序）

1. **token 地基**（随时可插、便宜）：把编辑器所有颜色收敛进一套有文档的 CSS 变量；theme 管道带「命名主题 id」；建共享 `.mica-acrylic` 类（亚克力靠 `backdrop-filter: blur() saturate()` + 半透明着色逼近，纯 RGBA 调不出 WinUI 多层叠加）。
2. **文件树重写**（先于完整主题系统——重写会新增可主题化的树行表面，主题先做会返工）。见记忆 [[planned-tree-and-theme]]。
3. **装饰层引擎 + 桌宠 widget**（两个一次性的承重件）。
4. **按数据产出各主题**（四季/星露谷/Claude）。可先做 Claude 薄片满足「热情驱动」。
5. **(可选，远期)** 薄的颜色微调 UI。完整可视化设计系统直接砍。

> 用户共识：先把功能做完，主题是锦上添花；但允许在「文件树之后」先切 Claude 主题薄片保持动力。

## 法律/版权备忘（开源、非盈利）

> 用户计划完全开源、不盈利。即便如此，第三方 IP 仍有风险，按下面把关：

- **clawd（Claude 吉祥物）**：是 Anthropic 的品牌资产，受版权（可能含商标）保护。开源/非盈利**不等于合法授权**，二次创作仍属衍生作品。**安全做法**：① 用**自己原创**、仅「致敬风格」的桌宠（别直接搬官方形象/名字）；或 ② 把 clawd 主题做成**可选下载的外部资源包**、不内置进仓库，降低仓库直接分发第三方资产的风险。把桌宠 widget 做成通用的，正好支持「换成自绘形象」。
- **星露谷物语**：游戏美术/字体/音乐均受版权，**像素素材不要直接提取游戏文件**。**安全做法**：自绘「田园像素风」原创素材（致敬风格、非复刻），命名上避免直接用商标（如不叫「Stardew」而叫「田园/农场」风格）。字体用**开源像素字体**（如 OFL 许可的），别用游戏内字体。
- **通用原则**：① 风格可以致敬，**具体表达（角色形象、logo、原画、字体文件、音乐）不可照搬**；② 商标名慎用在主题名/营销上；③ 所有内置素材确保是**自绘或明确可商用许可**（OFL/CC0/CC-BY 等，并保留署名）；④ 第三方 IP 浓度高的主题优先做成**外部可选资源包**而非仓库内置。
- **声明**：以上是工程经验层面的风险提示，不构成法律意见；真要上线/有疑虑时以正式法律咨询为准。
